用户提交单张图片和自然描述时，先调用只读 `avatar_inputs` 取得本轮附件的 imageRef，再将它作为 `image_ref` 调用 `avatar_make`，description 保留用户原话，rights 只填写实际许可或用户明确授权。支持 PNG/JPEG；图片不等于已有动态模型，后续须真实拆分、补绘和绑定。不得要求用户先提供 PSD 才接收单图。附件未登记时说明缺口，不猜路径或句柄。本轮重新附图并改变动作或配饰需求时，即使原图哈希相同，也须按本轮完整原文调用 avatar_make 创建新候选。同图历史任务的许可有明确来源时可沿用。用户选择现成分层素材时才调用 `avatar_materials` 并使用 material_id；两条路线不可混淆。

首次回复优先给真实任务 ID、已接收的图片和当前状态。简要复述用户明确提出的必保造型、动作和交付要求；未明确的运行器或制作细节可在后台分析。当前会话按本工作区工具回执查询进度和同版结果。新用户原图、候选与交付附件保持独立。

用户希望先拿到可用首包时，保留其首轮必做项及文件要求，后续按角色名、版本和具体反馈续修。只有模板的修改与交付许可、动作语义和网格适配都经核对，才进入模板复用。原生 `avatar_make` 暂无已验证的通用模板适配入口，按工具实际能力报告。只有同版运行包、预览和约定的可编辑资料实际可交付后，才报告首包已就绪。

收到 `DYNAMICS_ACTION_UNAVAILABLE` 时，按返回结果列出缺原生绑定配方的动作，保留用户原要求。只有新候选实际完成补绘、绑定、连续复核与同会话交付后，才报告对应的制作结果。

`avatar_make` 首次为本轮图片返回 queued 时，直接结束本轮并显示任务 ID 和后台接单状态。首次接单回合不调用 `avatar_making`，即使用户本来要求成品也一样。按工具回执区分在原会话自动发送结果和用户自行查询两种方式，不承诺固定出包时间。后续用户询问进度时先用原 ID 只读查询一次，wait_seconds、visual_page、visual_count 均设为 null。用户主动要求等待时，才用 wait_seconds:45 等待并沿同一个 ID 查询。worker_stopped 或 worker_unconfirmed 时先核对原任务状态；已经明确中断且能安全恢复时，只用一次 `avatar_make` 的 resume_job_id 恢复原候选。保留旧回执，不重新提交相同输入。

新图需要发送给 RunningHub 核价时，向用户展示本候选返回的 `/avatarupload` 命令和数据用途。真实报价返回后展示单价、输出数量范围和是否有硬封顶，按后端给出的完整 `/avatarpay` 命令由有权限的操作者在原会话确认。工具不代用户确认；本次额度只用于对应报价。此前已经授权且身份匹配的任务沿原回执继续。

用户要求继续原任务并且使用已登记的本地拆层时，直接用 `avatar_make` 的 `resume_job_id`；无需查询现成素材目录，不另开任务，不提外发或付费授权。需要等本次结果时，用原 ID 调一次 `avatar_making`。若返回 `pipeline.artwork.local`，从该字段报告已绑定的素材清单与实际缺件；`ARTWORK_QUALITY_FAILED` 时直接说明尚未绑定和出包，结束轮询。不要为了补齐说明再读整个阶段清单，也不要把本地拆层回执说成已完成的模型。

出现 visualReview 时，保留原 job_id，从 visual_page:0 配 visual_count:4 连续读取到最后一页；一组返回多张独立原分辨率图片，接着从该组末页加一读取，断线后继续未看的页。02 实看该候选的原图、重组、半闭眼、开嘴、移开刘海、举手和摘饰品等诊断图；静态图填 from=to=0，按照 evidence_by_criterion 为每项填写实际看过的 evidencePaths。03 核对各姿态和组合并带同版 evidencePaths，04 核对完整帧联系图。联系图只能支持动态缺陷记录，不能证明连续运动自然，不能提交动态通过；若无视频感知能力，明确报告“连续自审未完成”并保留待验。根据实际观察逐项填写 status、note、from、to，用 `avatar_make` 的 resume_job_id 和 visual_review 提交对应的 stage_sha256。视觉缺陷按实际交回；若工具已排队修复，仅等待原任务。标准 Flash 的额前遮挡或半闭眼缺陷可用缓存素材自动修一次，只有观察图已改变才会要求再审。静态素材视觉通过后继续等同一 ID。needs_input、failed、awaiting_external_result 和缺价格授权、无合格素材等真实 blocked 都要结束轮询，说明缺口及原任务身份。有未决外部作业时仅沿原回执恢复。

启用自动发送结果的任务由后台在原会话发布。其余任务在用户要求拿到成品且制作 completed 后，在同一回合调用一次 `avatar_deliver`，将同版模型与工程发布到 OpenClaw 官方媒体存储；将它实际返回的每个附件 path 逐行写成 `MEDIA:` 加路径，视频放在前面。预览说明标明制作引擎动画。附件未在原生页面显示或播放时保留待验，真人跟随和直播验收单独记录。

`avatar_making.steps` 是追加的执行历史。用顶层 status、stage 和当前 pipeline 状态报告进度，将旧步骤的 blocked 与当前阻点分开。
若 `avatar_making.completedCandidateDelivery.status` 为 `published`，同时说明该子修订已正式交付。顶层 revision、status 和 pipeline 仍描述父候选。

准备直播时先调用 `avatar_status`，需要运行模型时调用 `avatar_inspect`。查询不授权、不加载、不切场景。工具分项失败即实际阻点；顶层 ok 只代表查询完成，不代表应用或验收通过。

本机当前改走无需 Steam 的 VTubeLeaf 候选路线，先做同一制作模型的真人跟踪，之后再接 OBS/B站；不要求 Steam 登录、安装游戏或购买。以下 VTS 控制步骤只适用于实际选择 VTS 时，不能拿来控制 VTubeLeaf。后者尚无本项目已验证的对话控制适配；如未接通，明确说明并保留已完成制作结果，不伪造表情回读。实际安装与动作验证状态查项目 STATUS.md。



用户要准备预览时：
1. VTS 未安装/未开启 API：指出具体缺项。首次授权只在用户要连接时用 `avatar_connect`，让用户在 VTS 点允许；拒绝或超时停止申请。不要让用户粘贴凭据。
2. 从工具列出的实际角色及本项目 approvedModels 选择；无获准角色或缺文件就停止加载并说明。明确用户所选 model_id 后 `avatar_load`，不能因为查询而换角色。
3. 用 `avatar_expressions` 获取当前角色的文件、名称、顺序和热键。向用户列出真实结果；“第二个”指同一会话此前实际展示的第二项，不能再次排序后换指代。至少两个可复位表情才满足首版目标。
4. OBS 可连且没有输出任务时，用 `avatar_prepare_obs` 准备专属窗口源。工具不创建麦克风源、不抠像、不启动虚拟摄像头/录制/推流。仍需实看背景、边缘、半身构图；B站内声音单独选择本机麦克风。B站实际界面与输入列表未核对时，不声称预览已经接通。
5. 首次权限、登录和真人动作请用户在本机完成；只停在开播前预览。不要请求开播。

表情与恢复：
- 使用实际 expression_file、active=true/false。切换为另一个表情时，先停用本会话刚开启的前一个，再启用所指表情，不把所有基础服装/配饰表情关闭。工具自动保存第一次切换前完整开关基线。
- “再恢复”用 `avatar_restore`，以其回读结果为准。不要把关闭全部表情冒充恢复。
- OUTCOME_UNKNOWN / READBACK_FAILED：先 `avatar_status`、`avatar_expressions` 查询；不重复触发未知操作。可回到原会话恢复。SESSION_BUSY / MODEL_MISMATCH：说明原会话或角色不一致，不能强行覆盖。

交付边界：
保留实际会话回复和同版附件。没有实录就明确没有视频；没有 B站端实际运动、麦克风与回授检查就保持未通过。测试通过、静态截图和接口成功都不能代替真人动作验证。用户图片定制接收有使用与修改权的单张PNG/JPEG，不要求用户先准备PSD；后续须真实拆分补绘、导出，并在明确选择的运行器完成同版模型重载和动作检查。当前现成角色Demo不代表单图定制完成。
